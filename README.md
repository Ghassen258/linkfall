# LINKFALL — Network chaos, made visible

**A real-time, interactive network fault-injection simulator.** Launch packets into an eight-node topology, sever links mid-flight, and watch weighted shortest-path routing adapt. All traffic, queueing, packet loss, and statistics are generated by a real JavaScript simulation engine—not a prerecorded animation.

## Quick start

Requires a browser and Python 3 (for local serving). **No `npm install` or build step.**

```bash
python -m http.server 8000
# open http://localhost:8000
```

Native `.js` modules work with Python's standard HTTP server. Do not use `file://` directly because module loading can fail.

## Experiments worth trying

1. **Shortest route.** Traffic flows from `CLIENT` to `DB-01`, normally through `EDGE-01 → CORE-A → POP-EAST`. Inspect the green route and its total weight.
2. **Link failure.** Click **Inject failure**. Packets already using the failed link are dropped and new packets are routed along surviving connections.
3. **Total outage.** Click the line between `CLIENT` and `EDGE-01`, then select **Disable selected link**. No route exists; new packets are dropped with a `no route` event.
4. **Congestion.** Increase traffic above ~30 pkt/s. Links have distinct capacities; the simulator queues packets, computes load penalties, and reports buffer drops or timeouts if congestion persists.
5. **Change endpoints.** Choose a different source and target to watch the shortest route shift.
6. **Drag nodes.** Rearrange the animated topology without affecting the underlying graph weights.

### Networking model (read this)

This is an **educational synthetic simulator**, not a network packet capture or physical router emulator.

- **Path selection:** Dijkstra on an undirected weighted graph of **up** links. Live path selection can apply a congestion penalty based on observed in-flight packets and packets waiting at connected nodes.
- **Link capacity:** per-link admissions are rate-limited to a configured number of **packets per simulated second**. In-flight transmissions can overlap.
- **Packet travel:** an intentionally slowed synthetic travel animation (`185 + cost × 9` simulated milliseconds per hop), so individual packets are legible.
- **Metrics:** transit time is measured in simulation milliseconds, including animation time and queue delays. Routing costs are **not equivalent** to real-world ICMP latency, and no claims are made about real network performance.
- **Failure:** a link failure drops packets currently traversing that link. Other packets recalculate routes on the next hop. Disconnected destinations cause a `no route` drop.
- **High traffic:** a bounded packet buffer and queue timeout keep the simulation from growing indefinitely.

## Controls

| Action | How |
|---|---|
| Inject a link failure | **Inject failure** or press **F** |
| Repair all links | **Repair links** or press **H** |
| Pause / resume | Top button or **Space** |
| Inspect a link | Click a connection in the diagram |
| Disable / enable selected link | Link inspector button |
| Move a node | Drag it on the canvas |
| Adjust traffic / speed | Mission control sliders |
| Reset simulation data | Bottom of mission control panel |

## Tests

Node.js 20+ is used **only for running tests**, not running the application.

```bash
npm test
npm run check
```

All graph, routing, packet lifecycle, recovery, and buffer behavior are covered by automated tests. GitHub Actions runs both commands on push and pull requests.

## Deploy to GitHub Pages

Create a **public** GitHub repository called `linkfall`, push these files to `main`, then open **Settings → Pages → Deploy from a branch → main → /(root)**.

Expected published URL: `https://ghassen258.github.io/linkfall/` once Pages is enabled. All CSS/JS imports are relative, so the project works under a subpath.
